# Trail and debug clusters (LAY2, LAY6)

Plan item: `docs/superpowers/plans/2026-11-04-restructuring-cleanup.md`, LAY2 and LAY6, with decisions p1, q3 (reopened from q1), r1 (2026-11-04). This is a layout change: no behavior, no stored format, no crate graph change.

## Goal

Two file groups that are one responsibility each become a folder with a real parent module (`trail.rs` + `trail/`, `debug.rs` + `debug/`), and `debug_control.rs` (1,644 lines) is split by job. Every test keeps its id apart from the module path segment that moves.

## Target tree

```
crates/manifold/src/
  trail.rs                       mod history; mod nav; mod strip;       (declarations only, p1)
  trail/history.rs  + history/tests.rs   from nav_history.rs (1490)
  trail/nav.rs      + nav/tests.rs       from trail_nav.rs (941)
  trail/strip.rs    + strip/tests.rs     from trail_strip.rs (1032)
  debug.rs                       types (Job, DebugJob, ReaderOp, Line, Parsed), Verb and its row helpers, parse_line, print_help, MAX_WAIT_SECS, parse_secs   (q3)
  debug/verbs.rs                 the parsers, VERBS, and the four debug_* App helpers beside their rows
  debug/reader.rs                run_reader_op, spawn_stdin_reader, Waiters, HeadlessDebug, run_debug_job, debug_key_event
  debug/export.rs   + export/tests.rs    from debug_export.rs (693)
  debug/input.rs                 from event_loop/debug_input.rs (168)
  debug/tests.rs                 debug_control's test block (400): one file, since its tests drive `parse_line` over `VERBS`
```

Phases: **LAY2 first**, then **LAY6 after ARC1** (r1). The two do not depend on each other; LAY2 can ship alone.

## Rules

1. No re-exports (p1). A caller names `crate::trail::history::X`.
2. Module declarations: `main.rs` replaces `mod nav_history; mod trail_nav; mod trail_strip;` with `mod trail;`, and `mod debug_control; mod debug_export;` with `mod debug;`; `event_loop.rs` drops `mod debug_input;` and its `use crate::debug_control::debug_key_event;` becomes `crate::debug::reader::debug_key_event` (or moves with `input.rs`).
3. Visibility: items used across the cluster become `pub(super)` or `pub(crate)` only where a sibling now needs them; the move itself adds none for items already `pub(crate)`.
4. `use super::*;` in `trail_nav`, `debug_control` and `debug_export` names the crate root's items. One level deeper `super` is the cluster parent, so each becomes `use crate::*;` (same item set: a descendant sees the root's private items). `event_loop/debug_input.rs` is different: its `super` is `event_loop`, whose own imports (`debug_key_event`, `AfterCrash`, `Held`, `LeftClosed`, `winit::window::Icon`, ...) the glob also carried; `debug/input.rs` names what it uses explicitly, found by the compiler. The `mod tests` blocks' `use super::*;` keep meaning "the file under test" (for `debug::tests`, the items `debug.rs` and `verbs.rs` expose as `pub(super)`).
5. Test ids change only by the segment: `nav_history::tests::x` -> `trail::history::tests::x`, `trail_nav::tests::x` -> `trail::nav::tests::x`, `trail_strip::tests::x` -> `trail::strip::tests::x`, `debug_control::tests::x` -> `debug::tests::x`, `debug_export::tests::x` -> `debug::export::tests::x`, `event_loop::debug_input::tests::x` -> `debug::input::tests::x` (one test, `a_stalled_graph_ease_does_not_hold_idle_outside_the_graph`). Verification compares the sorted `-- --list` after mapping those prefixes; the diff must be empty.
6. Test blocks of 250+ lines go to `<file>/tests.rs` in the same commit as the move (TST1 rule), so each file moves once. `nav_history` 740, `trail_nav` 721, `trail_strip` 718, `debug_control` 400 and `debug_export` (249-251 by how the block is counted; borderline, moves with its file either way) qualify. Sizes are cfg-to-EOF counts.
7. Moves are `git mv` first, edits second, so the move shows at 100% similarity before content edits; the debug split is a second commit.

## Risks

- **Glob root imports (rule 4).** The one non-mechanical edit; a missed `use super::*;` fails to compile, so it cannot ship silently.
- **Branch `parked/idle-repaint-hook`** (625 behind main, 1 ahead) touches `event_loop.rs`, `main.rs` and `trail_nav.rs`; the overlap is mod lines and one trail_nav line. Weak evidence of no collision; say so when merging.
- **Visibility (q3).** `verbs.rs` reads `Verb`, `Parsed`, `Job` and `row`/`pointer_row` from `debug.rs`; `debug.rs` reads `VERBS` and the parsers the tests call from `verbs.rs`; `reader.rs` reads `DebugJob`, `ReaderOp`, `Line`, `parse_line`; `verbs.rs` calls `quit` and `debug_key_event`. Roughly 6 to 10 items gain `pub(super)`, found by the compiler; the four `debug_*` helpers and the parsers that `debug/tests.rs` calls are `pub(super)` (visible in `debug` and its children, so the tests see them). The `debug`/`verbs`/`reader` modules refer to each other (legal in Rust).
- **ARC1 ordering.** If ARC1 slips, LAY6 waits or edits the scanner path (r1/r2).

## Out of scope

Generalising `VERBS` (rejected in the survey), the JSON cluster (LAY3), `virtual_source`/`tree_layout` (shared with JSON, stay flat), any behavior change.
