# Live-state to document sync: map of today's flow (2026-10-05)

Facts gathered before planning 2b/2c of the node model (`2026-10-04-node-model-design.md`, section 6 items 6 and 10). Paths are under `crates/manifold/src/`; line numbers are as of commit 9a0e48a and will drift.

**Since 2b-5 the flow is the one in "After 2b-5" (end of this file).** `diff`, `explicit`, `keep`, `last_shared`, `Shared`, `shared_nodes` and `kind_fields` are gone; everything above that section, including "How it works" and "What diff does implicitly", describes the code as of 9a0e48a and each "After 2b-N" section as of its own plan, and is kept as history.

## How it works (as of 9a0e48a; superseded by "After 2b-5")

- **One production `diff` caller:** `save_session` (`session_sync.rs` ~970-1070) builds `live: BTreeMap<NodeId, Shared>` from `NodePayload` (`shared_nodes`, ~362-440; jars added as `Kind::Jar`; since 2b-3 a tab's url, engine, jar and jar_set come from the mirror, not the payload), takes `keep` from `spawning`, calls `diff(doc, live, explicit, keep)` and commits. Up to 4 rounds: pending remote ops are applied first, then the diff is recomputed. 18 test calls in `session_sync/tests.rs`.
- **No dirty flag, no timer for local edits.** About 45 call sites call `save_session()` directly after a mutation (card, tabs, fetched, graph_ui, graph_nav, node_menu, popups, settings_page, shortcuts, json_level, closed, main, event_loop, view_modes, image_view). `poll_store` runs every frame but saves only when the file changed on disk or a retry is due. Edits with no save of their own (pin shortcut, Pin All, note keystrokes) ride on the next save.
- **`explicit`** (`App.explicit`, filled by `App::mark`, cleared after a successful commit): since 2b-4 nothing marks any field, so it is always empty (`explicit_is_never_populated`) and `mark` is dead code until 2b-5 deletes it. Before 2b-4 the one site was `drag_moved` (POS, card.rs); before 2b-3 `navigate_tab` and the engine URL reports (event_loop.rs) marked URL. POS and URL stay `explicit: true` in `FieldDef`, but their mirror skip means diff never emits them for an existing node. PATH is the one explicit field diff still sees, and it is never marked (never written after create). POS from layout physics is never written (personal state keeps the layout pos).
- **`keep`**: built each round from `self.spawning` so a tab whose engine is respawning (crash, swap, wake, new tab) is not Deleted for lack of a live node; a spawning tab the document lacks is Created from `spawn_shared`.
- **Reverse path:** `remote_changes`/`apply_remote` (jars, then groups, then the rest) call `materialize` -> `update_live_node` / `insert_materialized`; `last_shared` plus a field-level guard keep unsaved local fields over remote edits to other fields (last writer wins per field).

## What diff does implicitly (a direct-op design must replicate or drop)

- Creates groups before members; a group created later in the batch (cycle) becomes top level.
- Never recreates a tombstone; never touches a non-live existing node.
- Writes an Id field as none when its target is neither live nor new (`valid`): every Id field of a `Create` (GROUP, PARENT, JAR, DEFAULT_JAR) and an existing node's diffed DEFAULT_JAR.
- Compares groups with `effective_group`, so re-homing out of a deleted group is not a Move.
- Sees cascades only as end states: children's `parent` passes up on node removal, dissolve moves members to the group's parent then deletes the group, `delete_jar` clears references then the jar is absent from `live`.
- Batches many frames of edits into one commit; refreshes `last_shared` by re-reading the document.
- Computed (not user-driven) changes to non-explicit fields are written like edits: `refollow`/cascade jar changes, fallback engine on spawn (since 2b-3 these go through `edit_jar` / `edit_engine`).

## After 2b-1

- Mirrored fields (`color`, `pinned`) are written only by `App::edit_field`, which updates the mirror and queues the op in `App::pending`.
- `save_session` commits `App::pending` beside `diff`, dropping edits for nodes this commit creates or deletes or the document doesn't show live, and clears it only on a successful commit.
- `mirror_remote` (called from `materialize`) skips a field with a pending edit, and `Mirror::init` seeds a new tab at spawn landing only if the id has no entry.

## After 2b-2

- Links (`group`, `parent`) live in the mirror. Only `edit_group` and `edit_parent` queue ops for them (`App::pending_moves`, `App::pending`); every local link edit, including local cascades (dissolve, merge, `remove_node`, `remove_tab`), goes through them.
- The other mirror link writers change the mirror only:
  - `mirror_remote` (from `materialize`): another replica's effective group and parent, skipping a link with a pending edit.
  - `follow_remote_group` / `follow_remote_parent`: a remote removal's cascade (`remove_remotely_deleted`, `dissolve_group_quietly`). Mirror only, so a concurrent remote merge, move or re-parent stands; a local edit still pending for the link is rewritten instead, so it keeps winning.
  - `Mirror::seed`: a landing tab (`seed_landing`) or a new node (`place_node`), only for an id with no entry.
  - `seed_landing`'s safety net: a new spawn whose group was removed while it was in flight lands in the document's group (nearest one still here), through `follow_remote_group`, never as a queued `Move`.
  - `save_session`'s post-commit alignment: a pending link whose target the commit wrote as none (Ruling 5) is none in the mirror too. A moved node's group is read back from the document (`effective_group`), not taken from the resolved target: the store refuses a `Move` that would close a cycle (a concurrent move can race into one), and the mirror then keeps the node where the document has it.
- Between a remote move landing (`mirror_remote`) and the next save, a local pending move can leave a group cycle in the mirror; two concurrent re-parents can leave a parent cycle in the document itself (the store doesn't cycle-check `parent`). Every walk up or down these links stops at a repeat: `group_breadcrumb`, `merge_groups` (refuses), `would_create_cycle` (true), `destroy_group`, `subtree_ids`, `inherited_jar`, `is_inside`, `governed_by`, `closed::members_under`.
- Cascades (`members_of`, `children_of`) also reach a tab mid-respawn: it is out of `nodes` but keeps its mirror entry. A new spawn has no entry until it lands.
- Commit order is `diff`, pending `Move`s, pending `Set`s, with targets resolved against the document and this commit; `diff` writes a created node's group or parent as none when the same commit deletes the target.

## After 2b-3

- **Mirror-only fields now:** `url`, `engine`, `jar` and `jar_set` join `color`, `pinned`, `group` and `parent`. `diff` skips them for an existing node; a Create reads them from the mirror (`tab_fields`, `spawn_shared`). `explicit` keeps only POS. The payloads no longer hold a jar (`TabPayload`, `UnloadedTabPayload`) or an unloaded tab's engine kind.
- **Writers:** `edit_url`, `edit_engine` (queues only when the decoded engine differs, so an unknown raw code survives), `edit_jar` (two `edit_field` calls, JAR and JAR_SET). `delete_jar` routes tab jars through `edit_jar`; a group's `default_jar` still lives on its payload.
- **Shared url vs live url.** The mirror (and the document) hold the *shared* url: the one a navigation started with, written by `navigate_tab` and the event-loop drain through `edit_url` (the last report in a drain that `shares_url_change` accepts). A move that is not shared stays in the live url only: a report the engine labels as not user-started is never shared, and an unlabelled one is held while a load the host started (`navigate_tab`, a remote url, a restore, a wake: `note_host_load`) settles. A link click (`user_started`) ends that hold, so an unlabelled redirect report after it is shared. The payload keeps the *live* url, which Recently Closed (`closed_entry`, `live_url_fields`) and the `LiveUrl` restore path keep recording. A landing tab seeds its url from its `TabSpawn` (`seed_landing`) and a placed node from its payload (`place_node`), both only when the id has no mirror entry, so a restore's live url is not taken as the shared one.
- **A pending local url beats a remote one.** `mirror_remote` returns the mirrored fields it held at a pending local edit, and `update_live_node` treats those as unchanged, so no `Navigate`, no `note_host_load` and no unloaded-url move happens for a remote url the mirror refused.
- **Id fields resolve at commit (generalized).** Every `FieldType::Id` pending field (PARENT and now JAR) is resolved against the document and this commit: a target that is neither live nor created becomes none, and the mirror is corrected to match (`set_parent` for PARENT, `mirror.set` for other mirrored Id fields). A Create resolves every Id field through `valid()`, and created tabs with a mirror entry get their JAR synced afterwards. Consequence (Ruling 8): a save no longer clears a dangling jar that another replica deleted; it stays as stored and the effective jar falls back to the default. A group's `DEFAULT_JAR` is still diffed (Ruling 11), so it is the exception: a save writes a remote-deleted default as none, while the group payload keeps the dangling id, so new tabs in that group start on a missing jar (the default) until the group's default is set again.
- **jar and jar_set are independent fields, so last-writer-wins is per field and can mix a choice.** A local follow-group-jar edit changes only JAR_SET; if a remote replica picked a specific jar (JAR) at the same time, the result can be the remote JAR with the local JAR_SET. Accepted; replicas converge on the mixed value.
- **Engine is written at swap or wake start.** `start_swap_to` and `wake_tab` call `edit_engine(target)` before the state snapshot or spawn, so the mirror, document and saved session name the target while the tab still runs the old engine (`EngineTab.kind` is the running engine). A failed spawn's fallback writes the old engine back (`edit_engine(fallback)`).
- **`App::swap_in_flight(id)` is the one-swap lock:** `swap_target`, else the target of a `Held::Snapshot` parked in `cookie_holds` (a swap waiting for its cookies, and also "Switch Jar Now", whose hold is on the running engine). `start_swap_to` refuses while it is set, so a local pick during the window is dropped silently, and a remote engine change does not start a second swap. The window has two phases: `swap_target` lasts until the old host's snapshot arrives (unbounded for a host that never answers), then the parked snapshot lasts until the cookies arrive or `COOKIE_HOLD` (2 s) passes.
- **Reassert (accepted, review M1).** While a swap is in flight, a remote engine change accepted into the mirror is overwritten at once with the in-flight target by `update_live_node`. This also holds after the swap's own edit has been saved, and for a swap another replica started that this replica is running: a later remote engine change loses to the target. A "Switch Jar Now" hold (`Held::Snapshot` on the running engine) counts as in flight too, so a remote engine change in its window (up to 2 s) is overwritten with the *running* engine though no swap is happening; accepted with M1.
- **Mid-swap crash, sleep, duplicate.** A crash mid-swap finishes the swap: the tab restarts on `mirror.engine(id)` (the target) with the running engine as `fallback_kind`, and `leave_crashed_card` shows the target. Sleeping mid-swap keeps the target (an unloaded card carries no engine, so the mirror's wins), and `duplicate_tab` duplicates onto the target.
- **Raw unknown engine codes are preserved.** `Mirror::engine` decodes through `engine_of` (absent, 0 or unknown reads as Servo); `Mirror::engine_code` and `Carried.engine` keep the raw code, and `edit_engine` writes nothing when the decoded engine already matches, so a code from a newer build survives saves, sleep and wake.
- **Remote changes parked for a spawn replay at landing.** A remote change to a tab whose spawn is in flight is parked (`remote_in_flight`) and applied by `land_remote_in_flight` -> `materialize`, which compares against `last_shared`. The commit refresh skips a tab with a parked change, so `last_shared` stays what this replica saw before it and the landing still sends `Navigate` or starts a swap (final review I1), even after a local commit (a Delete, a jar cascade) re-read the document in between.
- **A new spawn whose jar is deleted mid-flight lands on the default jar.** `delete_jar` cannot reach it (no mirror entry), so `seed_landing` clears a jar missing from `jar_defs` through `edit_jar`, which also fixes the document whether the tab's `Create` committed before the delete (with the jar) or after (with none). A tab with an entry keeps a dangling jar (Ruling 8).
- **Known gaps, parked:** the post-commit mirror correction for created tabs covers JAR only, not PARENT; a pending Set equal to the stored value is still written; `navigate_tab` and the event-loop drain's `edit_url` call sites have no test.

## After 2b-4

- **Mirror-only fields now:** `pos`, `text`, `view` and a group's `name` join the 2b-1..2b-3 fields. `diff` skips all of `MIRRORED` for an existing node; a Create reads them from the mirror (`shared_nodes`, `spawn_shared`). A jar's NAME is still diffed (`jar_defs`, sub-project C). `explicit` is never filled.
- **Document pos vs layout pos.** `Mirror::pos(id)` is the document pos (`None` when absent; Pos (0,0) is the absent value). What the graph draws is `App::layout: HashMap<String, Layout { pos, vel }>`, a runtime side-table keyed by id: physics, settle and a drag move only it, and every reader (drop targets, focus moves, marquee, centroid, transitions, edges, `card_rect`) reads it. `layout_pos` reads ZERO for an id with no entry. The table is pruned at a successful save to ids in `nodes` or `spawning` (next to `mirror.retain`) and cleared at teardown, so a respawn or wake keeps its entry and `TabSpawn`/`TabCarry` no longer carry pos or vel. *(Since 2026-10-27 the layout is a plain position with no vel, a settle starts from the document pos (`settle_current_level`), pinning saves the shown pos first (`set_pinned`), and personal state records no position, so the restore and "personal pos seeded" lines below no longer hold.)*
- **Only two things write the document pos:** a drag release (`release_drag` -> `edit_pos` for the grabbed card and every card in `drag_moved`, with each one's layout pos) and placement at create.
- **Placement at create (2b-4 Ruling 3).** `place_node` seeds the mirror's POS with the placement (`Carried.pos`, through `Mirror::seed`, so only for an id with no entry) and snaps the layout there; a new tab's `spawn_shared` writes its `TabSpawn.pos`. A Create therefore stores where the node was placed, not where physics settled it by the first save. `seed_landing` inserts the layout entry only if absent, so a respawned tab stays where its card was.
- **Remote pos snap rule.** `mirror_remote` takes another replica's POS unless a local one is pending (local wins, 2b-3 Ruling 3). `update_live_node` then snaps the layout to it and zeroes its vel, except for a card being dragged (`is_being_dragged`: while a drag is live, the grabbed card or a card moving with it in `drag_moved`); that drag's release then writes the local pos over it. A drag stops being live when the grabbed card leaves the level shown or Graph view is left; `end_stale_drag` (each frame and at `switch_group_level`) then clears `dragging` and `drag_moved` with no drop, so a later release can't write a stale layout pos over a remote one.
- **Restore.** The mirror gets the document pos; the layout gets the personal `LocalNode.pos` (personal state records the layout pos) if there is one, else the document pos (`apply_local`, `apply_pending_local`). Recently Closed records the layout pos (`closed::live_fields`, Ruling 10), so a node reopens where it was shown.
- **Text: the payload is the edit buffer, the mirror is the committed text.** `NotePayload.text` stays a full copy (so a 1 MB note is held twice). The box edits the payload; nothing writes the mirror per keystroke. `edit_text` (compares first, so equal text copies nothing) runs at blur (`blur_note` -> `end_note_edit`, then a save) and at the top of every `save_session` (`commit_note_buffers`: every note whose buffer differs from the mirror, typed in or not). Readers: `App::note_text` (the buffer while `NotePayload::editing`, else `Mirror::text`, both borrowed); the idle Markdown render reads `Mirror::text`. Recently Closed records `note_text`, so a note closed mid-typing keeps what was typed.
- **Text held while typed in, resolved at blur (Ruling 7, as implemented).** "Typed in" is the `NotePayload::editing` flag (`is_typed_in`), not egui focus. A remote TEXT for such a note is held: `mirror_remote` returns it as held (so the box is not overwritten) and remembers it in `App::held_text` (or drops the entry if the remote value equals the mirror). At blur, if the buffer equals the mirror (the last commit) and no TEXT edit is pending, the held text applies to the mirror and the box; otherwise the buffer is committed (`edit_text`) and the held text dropped. A successful commit that carried a pending TEXT drops that note's held entry (the local commit is newer), and the save prunes `held_text` to notes still being edited. Two consequences:
  - The rule is "changed since the last commit", not "since focus" (accepted 2b-4 deviation): a user who typed, was saved by a periodic save, then stopped typing sees a remote text that arrived after that save replace theirs at blur (last writer wins). Reading it as "since focus" would have left the mirror showing the local text while the document held the remote one.
  - A note with `editing` set but no focused box (a restored note whose personal state said `editing`, or a new note that never got focus) holds remote text with no time limit, until the box is laid out and blurs or `end_note_edits` ends the edit.
- **View: the mirror holds the stored `Str` plus a decoded cache.** `Mirror::set` (the one writer of every mirrored field: `init`, `edit_field`, `mirror_remote`, `end_note_edit`, `place_group` and the post-commit corrections) refreshes `views` whenever VIEW is set; an empty view removes the entry, and `retain` drops it. `Mirror::view(id) -> Option<&JsonView>` is the per-frame reader (level layout, `sync_json_level`, `reveal_json`, the card tint and menu colour); nothing parses per frame. `edit_view` is the writer: `edit_json_view` clones the cached view, applies the edit, prunes, writes the stored text, relays out and saves. A remote VIEW marks the level shown stale. `JsonPayload::view` is gone.
- **A reload keeps the view** because the mirror entry outlives `reload_fetched_node`'s remove and reinsert. Overrides the new value can't resolve are pruned through `edit_view`, so the prune is a pending local edit until the next save: a remote view edit arriving before then loses to it (last writer wins per field, accepted). A Create writes the mirror's raw VIEW string; it is no longer re-encoded through `JsonView` (canonicalized) on the way.
- **Name: groups only.** `Mirror::name(id) -> &str` borrows ("" when absent); `edit_name` (compares first) is called by `CommitRename`. A new group's name is seeded by `place_group`, only when the id has no mirror entry at all (`mirror.has`, nodes or links), while `place_node` seeds through `Mirror::init` (no field entry); a stored group gets NAME from `mirror_remote` before `insert_materialized`. `GroupPayload::name` is gone, so every reader goes through `Mirror::name` with a `// name rule:` mark (names.rs guard). `App::own_text` returns a group's raw stored name for the card filter and `accessible_name`: a caller that draws it must apply a name rule itself.
- **Known gaps, parked:** a node in neither `nodes` nor `spawning` at a save loses its layout entry (none found, but an id removed and reinserted outside `spawning` across a save would land at its document pos); a restored node whose stored fields include no MIRRORED field gets its personal pos seeded into the mirror as its document pos; `wake_tab` and `TabSpawn::respawn` compute a pos nobody uses; the card.rs drag body has no unit test; no two-instance scenario covers rename, text or view.

## After 2b-5

- **Everything stored is mirror state.** Group, leaf and content fields (2b-5 Task 1: f032489, 4b57c18) and jars (Task 2: 0bdf7d3, 6052e43) join the earlier fields. `diff`, `explicit`, `keep`, `last_shared`, `Shared`, `shared_nodes`, `kind_fields` and `MIRRORED` are deleted (4b928c3, 05d31cc); each type's field list is a column of the `TYPES` table (`Kind::fields`). `save_session` no longer derives ops by comparing live state with the document: it commits what was queued.
- **Creates and deletes are queued ops.** `queue_create` / `queue_delete` (`session_sync.rs`) fill `App::pending_creates` / `pending_deletes`; every create funnel (`place_node`, `spawn_tab_async`, `create_jar`, `materialize_imported`) and every destroy path calls them, and each withdraws the other for the same id. At commit:
  - a create is written only for an id the document has no entry for at all (a tombstone is never recreated; a node another replica created stands), from `App::snapshot`, which projects (type, fields, group) from the mirror; a node that shows nothing yet (an in-progress download) waits; a new tab is created while its spawn is in flight, from the spawn snapshot;
  - a delete is written only for a node the document still shows live ("queued and doc-live"); one it never had, or another replica deleted, is dropped;
  - Order is Creates (groups first), pending `Move`s, pending `Set`s, then Deletes, up to 4 rounds; a failed commit leaves the queues, a successful one clears them.
- **One Id resolver.** `resolve_id(doc, created, deleted, target)` turns every Id field (GROUP, PARENT, JAR, DEFAULT_JAR) of a Create, Move or Set into none when its target is neither live nor created in this commit, and the mirror is corrected to match after the commit.
- **Test-build invariant.** `check_graph_matches_document` (`cfg(debug_assertions)`: tests and debug app runs) asserts after a save that every shown node (an in-progress download and a spawning tab excepted) is live in the document, so a missed create funnel fails a test rather than losing data.
- **Jars live in the mirror.** A jar is a node row in the mirror; `Mirror::jar_defs()` holds a `JarDef` cache refreshed whenever a jar field is set, and every reader (`resolved_jar`, menus, cookie code) reads `self.mirror.jar_defs()`; `App.jar_defs` is gone. A remote jar rename or ephemeral toggle is compared against the mirror, and an unsaved local rename or ephemeral change now beats a remote one (behavior change). A remote-deleted default jar stays stored (Ruling 6).
- **`mirror_remote` returns `(held, changed)`.** `held` is the fields a pending local edit refused; `changed` is the fields whose mirror value actually differed. `mirror_remote` writes only on a difference, and `update_live_node` applies only the changed fields, which replaces the old compare against `last_shared`. A remote change parked for a spawn in flight is replayed at landing the same way.
- **Pending-delete resurrection guard.** `materialize` (and `materialize_jar`, which runs before `mirror_remote`) drops a remote change to a node or jar whose delete is pending, so a remote edit cannot re-show something the user just closed before the save lands; showing it again locally withdraws the delete (`queue_create`).
- **Snapshot for Create and Recently Closed.** `App::snapshot` reads a node's (type, fields, group) from the mirror; Create commits and `closed::` entries both use it, so a node mid-spawn is recorded through the same fallback (`spawning`). `worth_reopening` takes the type string (`Mirror::ty`), and the caps bridge no longer reads `store_node`.
- **Known gaps, parked:** `Kind::from_type` maps `image/*` to Image, so TYPE is canonical, not raw (2b-6); a failed download stays in `pending_creates` for the run; `pending_deletes` never clears on a read-only store; `LiveUrl.from` is the mirror url, so an unsaved tab records a live_url and an unsaved `edit_url` does not.

## After 2b-6

- **A card's identity is its type.** `App::card_kind(id)` (`card_kind.rs`) returns `CardKind { ty, tags }`: `ty` is
  `Mirror::ty` canonicalised through `Kind::from_type(..).type_str()`, and `Tag::Loaded` is set when the runtime is a live
  tab. Draw order, restorability and containment read `caps(type)` and the edge table from it. Not every decision does:
  click action, the Del verb, card style, the body painter, menus and parts of `drop_action` still `match` on the type
  constant (`TYPE_*`), and card size and filter text match on `Runtime`. No enum of kinds remains. `Tag::Loaded` is produced there and matched by the tab/unloaded rows (a loaded tab wins by rank).
- **Live data is a side table.** `App::nodes: HashMap<String, GraphNode>` stays "shown in the graph"; `GraphNode.runtime` is
  `enum Runtime { Tab, Unloaded, Download, Note, Image, Pdf, Json, None }` (`node.rs`) holding only what the mirror cannot
  (webview, edit buffer, decoded image, ...). A group has `Runtime::None`; the as_x accessors keep their names. The document
  fields (url, text, name, view, ...) are mirror state, as since 2b-5.
- **No payload or item enums.** `NodePayload`, `GroupPayload`, `ItemNodeKind` and the caps bridge are gone, and a source
  test (`deleted_names.rs`) keeps them gone. `LevelItemKind` is `Node(CardKind)` or `JsonCard`.
- **One-pass level scan.** `App::level_scan()` (`level.rs`) walks `node_order` once, keeps the nodes in the current level and
  buckets them by `Caps::draw_layer` (`LevelScan::layers`, plus `groups` for containers); `build_graph_ui` draws layer by
  layer. It replaced eight per-kind scans (`nodes_at_current_level(kind)`).
- **EXPORTSTATE** `cards[]` carries `type`, `loaded` and `json_card` instead of `kind`; `scripts/export_state.py` offers
  `card_is(card, TYPE, loaded)` and a `type[;loaded]` label (`json-card` for a JSON level's card) to the probes.
