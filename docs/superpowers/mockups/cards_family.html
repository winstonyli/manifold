Card family in design F

Every card kind with the approved tab-card layout: a 40 px header (glyph or favicon, name, a dim second line chosen by one rule: the web address if the card has one, else the file path, else other data (a group's item count, a note's word count); state icons) above its content. The second line is data the app already holds for every kind except Group: tabs have a URL; images, PDFs, JSON and notes have an optional web `url` and always a local `path`; downloads have a `path`. A long local path is cut at its start, so the file name stays visible; a web address is cut at its end. Content stays what each kind shows today (page thumbnail, image, PDF page, note text, JSON preview, child tiles, progress); only the header is new and shared. The note keeps its yellow paper.
