# UI mockups

HTML sketches from the design sessions, recovered from the session transcripts (2026-10-01); open them in a browser (they load Google Fonts and Tabler icons from CDNs).

- `toolbar_redesign_sketch.html` (2026-09-23): three toolbar concepts. **Option A, segmented chips, was approved**: raised chips with ghost icons, hairline dividers between chips, one solid-gold primary action, soft-filled fields. Implemented by `toolbar_chip`, `primary_button` and `toolbar_panel` in `crates/manifold/src/theme.rs`.
- `spacing-options.html` (2026-09-20): compact vs airy. Chosen: airy for dialogs and settings, compact for the graph toolbar; menus were later made compact too (`menu_item_style`).
- `heading-final-v2.html`, `editorial-options-visual.html` (2026-09-20): heading font and palette explorations behind the editorial retheme.

Compare with the running app using `gate chrome-shots`.
- The engine-install rows (picker state lines, Settings Engines section, the download confirm, the failed-tab card) have no mockup: they were built straight in egui and checked with the `engine-states-*` and `engine-install-confirm` views of `gate chrome-shots` (2026-10-02).
- `toolbar_v2.html` (2026-10-01): self-contained (inline SVG icons, no CDN or host CSS variables, which is why the older sketches above render unstyled and iconless outside their original chat widget). Both bars built from the app's real controls: one button and field anatomy, 38 px bar, chips per cluster, icon-first, an inset field with hairline border and accent focus ring. A proposal, not yet implemented; the app currently differs in bar height (32 px), the text "Graph"/"Split"/"Tab actions" buttons and the borderless address field.
- `toolbar_fonts.html` (2026-10-01): the toolbar_v2 bars in 14 faces (Literata and Newsreader from `crates/manifold/assets/fonts`, the rest Windows system fonts), generated from `toolbar_v2.html`. Needs about 820 px of width; narrower panes scroll sideways.
- `toolbar_sans.html` (2026-10-01): the same bars in 16 open-licence sans faces (Inter, IBM Plex Sans, Manrope, DM Sans, Figtree, Plus Jakarta Sans, Instrument Sans, Schibsted Grotesk, Geist, Onest, Outfit, Sora, Atkinson Hyperlegible, Bricolage Grotesque, Familjen Grotesk, Space Grotesk) plus Literata for reference, ordered roughly neutral to idiosyncratic. Loads from Google Fonts, so it needs a network connection; any chosen face would have to be bundled (OFL) in `crates/manifold/assets/fonts`.
- `toolbar_grotesque.html` (2026-10-01): shortlist from `toolbar_sans.html`, narrowed to four grotesques (Schibsted, Familjen, Bricolage, Space) with Literata as reference. Each face shows the graph bar, tab bar, a focused long-URL field, a menu with shortcuts, a settings panel, a card header over Literata body text, the Ctrl hint strip, keycap badges, a tooltip, an 11-15 px size ladder, numerals and a weight check. Buttons switch control size 12/13/14 px. Needs network (Google Fonts).
- **Decision (2026-10-01): Familjen Grotesk** is the chosen toolbar/control typeface (OFL, from the `toolbar_grotesque.html` shortlist). Scope proposed, not yet confirmed: controls only (toolbars, menus, buttons, hints); Literata stays for body text and Newsreader for headings. Not yet bundled or wired in.

**2026-10-02, download in flight.** `download-progress` shoots a real download stalled at 300 KB of 1 MB: header with the URL, "293.0 KB of 976.6 KB" mid-body, and the bar below, all fitting the 40 pt header layout. Not shot because it cannot be reached: a failed or cancelled download. The engines send only `DownloadStarted`, `DownloadProgress` and `DownloadCompleted`, so a cancelled one stays at its last progress forever (and, since the idle sweep treats an unfinished download as busy, keeps its tab awake). Showing it needs a `DownloadFailed { path }` message from each engine first.

**2026-10-02, failed download.** New `EngineToHost::DownloadFailed { path }` (WebView2 `INTERRUPTED`, CEF cancelled/interrupted, WebKit `failed`; WebKit's `finished` follows a failure, so it is suppressed). The host sets `DownloadPayload.failed` (not stored: only completed downloads are), toasts "Download failed: <path>", and the card shows "Download failed" in the danger colour with no bar; the Downloads popup row says "Failed", and the idle sweep no longer counts the tab as downloading.
