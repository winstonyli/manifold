# Links and menu-driven edges Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Users can link any two cards and set a card's opener from the node menu, and disconnect either, with links stored as a new `Link` node kind.

**Architecture:** A `Kind::Link` stored node (`from`, `to`, `name`) handled like a jar (store and mirror state, never a graph card). The edge table gains the columns B needs and two user-creatable rows (`opened-from`, `link`). One pair of `App` functions, `connect` and `disconnect`, is the only way menus and the drag-reparent change an edge. Links draw as a second edge source and never feed the layout's springs.

**Tech Stack:** Rust, egui; the session store (`crates/manifold/src/store`), `Mirror`, `session_sync`.

**Spec:** `docs/superpowers/specs/2026-10-06-links-design.md`. Research on touched code (file:line facts): `.superpowers/sdd/links-research.md` (git-ignored; re-derive with grep if absent).

## Global Constraints

- Work on `main` (CLAUDE.md "Branches"); no worktree. Commit per task.
- `cargo fmt --all` before each commit; `cargo clippy -j 8 -p manifold -p ipc-protocol -p manifold-engine-webview2 --all-targets -- -D warnings` must pass; `.githooks/pre-commit` runs both (commit in the background, it takes 2+ minutes). Never `--no-verify`; do not silence a lint without a comment saying why.
- Use `-j 8` on cargo; run builds and tests at BelowNormal where practical.
- No test may touch the real `%APPDATA%\manifold`: use `store::testutil::temp_dir` and `app_on(&path, n)`.
- Python only via a script file and `python -P f.py < /dev/null`; never `python -`, heredoc python, or a no-op python call. Prefer the Edit tool. Subagents must never dispatch subagents.
- Spec values: type string `application/vnd.manifold.link`; fields `from`, `to` (Id), `name`; `link` is any card to any card, many, not acyclic, does not move nodes; `opened-from` stays at-most-one, acyclic, moves nodes; targets are same-level only; menus only (no drag, no click on a line).
- Card types for the new rows: the `contains` source list in `caps/edges.rs` minus `TYPE_JSON_LEAF` (JSON-level cards are not stored nodes).

```rust
#[derive(Debug, PartialEq, Eq)]
pub(crate) enum ConnectError { NotAllowed, NotLive, DifferentLevel, Cycle, Exists }

pub(crate) struct EdgeRef { pub edge: &'static str, pub other: String, pub link: Option<String>, pub outgoing: bool }

impl App {
    pub(crate) fn connect(&mut self, edge: &str, from: &str, to: &str) -> Result<(), ConnectError>;
    pub(crate) fn disconnect(&mut self, edge: &str, from: &str, to: &str);
    pub(crate) fn edges_of(&self, node: &str) -> Vec<EdgeRef>;
    pub(crate) fn valid_targets(&self, edge: &str, from: &str) -> Vec<String>;
}
```
`connect` checks, in order: row exists and is user-creatable-or-tree (`can_connect` on both nodes' types from `Mirror::ty`), both live in `self.nodes`, `in_level` equal, `acyclic` (`would_create_cycle` for `opened-from`), and for `link` that `links_naming(from)` holds no link whose other end is `to` (either order). It writes `edit_parent(from, Some(to))` for `Storage::Field(PARENT)` or `create_link` for `Storage::Node`. `disconnect` writes `edit_parent(from, None)` or `delete_link`. `edges_of` returns the node's opener (outgoing), the nodes it opened (incoming), and its links (`link: Some(id)`). `valid_targets` is every node at the level for which `connect` would succeed.
