# On-Demand CEF Install Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Packaged builds download CEF's runtime on demand from CEF's CDN (pinned URL + SHA-256 compiled into the app), with every engine's availability shown explicitly everywhere engines are listed.

**Architecture:** A new `engine_install` module holds the pure parts: the pin, the availability state function, a resumable download, SHA verification and a safe unpack. The app runs an install job on a worker thread and reports progress through the existing event path. `engine_binary_path` consults the install marker. The UI reads one `engine_availability` function.

**Tech Stack:** Rust, egui 0.36, `ureq` 3 (already a dependency), `sha2` 0.10/0.11, `sha1` 0.10/0.11, `bzip2` 0.6.1 (default feature: pure-Rust `libbz2-rs-sys`, no C toolchain; never enable `bzip2-sys`), `tar` 0.4.46. All are already in `Cargo.lock` (via the cef build dependency); add them to `crates/manifold/Cargo.toml` at those versions. Surveyed 2026-10-02 and rejected: reusing `download-cef` (always pulls clap/indicatif/regex, no Range resume, no cancel or progress callback, no SHA-256, moves unwanted directories) and shelling out to `tar.exe` (no progress or path control).

**Spec:** `docs/superpowers/specs/2026-10-02-engine-install-design.md`

## Global Constraints

- Servo stays bundled; WebView2 is the default and always present; WebKit unchanged. Only CEF is downloadable.
- Engine states are exactly: Installed, Not installed, Installing, Update needed, Failed, Custom. No silent fallback to another engine and no silent install.
- A download needs a size-stating confirm first (e.g. "Download CEF, 172 MB?").
- Verify SHA-256 (our anchor) and SHA-1 (index) before unpacking anything. A partial or unverified runtime must never be visible at the final path.
- No test reads or writes the real `%APPDATA%\manifold` or the real engine data directory: paths come from `profile::engine_data_dir()` (`None` under `cfg(test)`) or are passed in; tests use `store::testutil::temp_dir` (see repo CLAUDE.md).
- Work on `dev`; `cargo fmt --all`; `cargo clippy -p manifold -p ipc-protocol --all-targets -- -D warnings` must pass; never `--no-verify`; no push or release.
- Python helper scripts run as `python -P file < /dev/null`.
- Pin values: CEF 152.0.6 (`152.0.6+g708dc14+chromium-152.0.7977.83`), `minimal` Windows x64 archive `cef_binary_152.0.6+g708dc14+chromium-152.0.7977.83_windows64_minimal.tar.bz2`, 171,619,649 bytes, SHA-1 `e5e3020627f4528bd43e22f4c4970000b0458e99`, from `https://cef-builds.spotifycdn.com/` (URL-encode `+` as `%2B`).

## File Structure

- Create `crates/manifold/src/engine_install.rs`: `Pin`, `EngineState`, `engine_availability`, `download`, `verify`, `unpack`, `install`.
- Create `crates/manifold/src/cef_pin.rs`: the compiled-in `CEF_PIN` table (generated by the script, checked by a test).
- Create `scripts/cef-pin.sh` (+ `scripts/cef_pin.py`): reads `index.json`, downloads once, writes `cef_pin.rs`.
- Modify `crates/manifold/src/process_manager.rs`: `engine_binary_path` checks the marker.
- Modify `crates/manifold/src/main.rs` (state fields, `mod` lines), `event_loop.rs` (install events), `popups.rs` / `engine_info.rs` (states in pickers and cards), `settings_page.rs` (Engines section, BYO directory), `settings.rs` (the "CEF directory" setting).
- Modify `scripts/chrome-shots.sh`, `README.md`, the spec.

### Task 2: Resumable download with hash verification

**Files:** Modify `crates/manifold/src/engine_install.rs`, `crates/manifold/Cargo.toml` (`sha2`, `sha1`, versions as in the Tech Stack line).

**Interfaces:**
- Produces: `pub(crate) fn download(url: &str, part: &Path, total: u64, progress: &mut dyn FnMut(u64), cancel: &AtomicBool) -> Result<(), InstallError>` (resumes from `part`'s length with `Range: bytes=N-`; if the server answers 200 instead of 206, restarts from 0); `pub(crate) fn verify(path: &Path, pin: &Pin) -> Result<(), InstallError>`; `pub(crate) enum InstallError { Network(String), Cancelled, BadHash { want: String, got: String }, Unpack(String), Io(String) }` with `Display`.

- [ ] **Step 1: Failing tests** using a small `std::net::TcpListener` HTTP server in the test module that serves a byte buffer, honouring `Range`, and a variant that closes the connection after N bytes:
  - `download_fetches_everything`
  - `download_resumes_after_a_cut_connection` (first call fails with `Network`, `.part` keeps the partial bytes, second call completes, file equals the buffer)
  - `download_restarts_when_the_server_ignores_range`
  - `download_stops_when_cancelled` (returns `Cancelled`, `.part` kept)
  - `verify_rejects_a_wrong_hash_and_accepts_the_right_one` (compute the expected digests in the test)
- [ ] **Step 2: Run to verify failure.**
- [ ] **Step 3: Implement** with `ureq` (read in 64 KiB chunks, append to `part`, call `progress(total_so_far)`, check `cancel` between chunks). `verify` streams the file through SHA-256 and SHA-1 and compares both.
- [ ] **Step 4: Run tests** → pass; fmt; clippy.
- [ ] **Step 5: Commit** `engine_install: resumable download and hash verification`.

### Task 3: Safe unpack and `install`

**Files:** Modify `engine_install.rs`, `Cargo.toml` (`bzip2` with default features, `tar`; versions as in the Tech Stack line).

**Interfaces:**
- Produces: `pub(crate) fn unpack(archive: &Path, into: &Path, pin: &Pin) -> Result<(), InstallError>` (extract only entries under `<top>/Release/` and `<top>/Resources/`, flattening both into `into`, skipping `libcef.lib`, `*.lib`, `include`, `cmake`, `libcef_dll`, `CMakeLists.txt`, `debug.log`; reject any entry whose path escapes `into` — `..`, absolute paths, symlinks; write `MARKER` last); `pub(crate) fn install(pin: &Pin, data_dir: &Path, progress: &mut dyn FnMut(u64), cancel: &AtomicBool) -> Result<PathBuf, InstallError>` (download to `data_dir/cef-runtime.part` → verify → unpack into `data_dir/cef-runtime.tmp` → remove an old `cef-runtime` → rename → delete `.part`; on a hash or unpack failure delete `.tmp` and the `.part`, on a network failure keep `.part`).

- [ ] **Step 1: Failing tests** with a tiny `tar.bz2` built in the test (via the same crates): contains `top/Release/libcef.dll`, `top/Resources/resources.pak`, `top/include/x.h`, `top/Release/libcef.lib`, plus a second archive with a `../evil` entry.
  - `unpack_keeps_runtime_files_and_drops_leftovers`
  - `unpack_refuses_a_path_that_escapes`
  - `install_end_to_end_against_the_local_server` (uses a `Pin` built in the test with the archive's real SHA-256/SHA-1 and the server URL; afterwards `runtime_state == Ready`)
  - `a_bad_hash_leaves_no_runtime_directory_and_no_part_file`
  - `a_network_failure_keeps_the_part_file_and_the_previous_install`
- [ ] **Step 2: Run to verify failure.** **Step 3: Implement.** **Step 4: Run tests; fmt; clippy.**
- [ ] **Step 5: Commit** `engine_install: safe unpack, atomic install`.
