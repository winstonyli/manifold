# Lazy Tabs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A restored session starts one engine, the focused tab's; every other tab sleeps as a card until it is opened.

**Architecture:** The failed-tab card (`FailedTabPayload`) widens into an unloaded tab (`UnloadedTabPayload`) with a state: sleeping, waking or failed. Restore inserts sleeping cards instead of spawning, then wakes the focused one. Everything that opens a tab goes through `focus_tab`, which wakes an unloaded tab through `wake_tab` (the old `retry_failed_tab`) with a new `SpawnPurpose::Wake`.

**Tech Stack:** Rust (crate `manifold`), egui, the session store (`crates/manifold/src/store/`), headless bash scripts under `scripts/`.

**Spec:** `docs/superpowers/specs/2026-09-27-lazy-tabs-design.md`. This plan amends it in five places; Task 5 writes the amendments into the spec:

1. **Wake landing.** Opening a tab sets focus and Tab view at once, and Tab view shows the existing "respawning" placeholder until the engine lands. The landing then behaves like a crash respawn (`Respawn`): visible if still focused, background otherwise. It does not call `focus_tab` itself, so a user who went back to Graph meanwhile stays there. `SpawnPurpose::Wake` exists only so the landing calls `note_host_load` (a host-started load) at the moment the engine starts; calling it at spawn time would let the grace window expire during a slow spawn.
2. **Open Session sleeps too.** `replace_running_session` (Open Session, `OPENSESSION`) replaces the whole session, as a launch does, so its tabs restore asleep and the focused one wakes. Group import and Recently Closed still spawn.
3. **No border change.** A failed card never had a `DANGER_COLOR` border. The failed-only red is the minimap dot, which sleeping and waking tabs draw in the tab color.
4. **The payload keeps `muted`** as well as `title`, so personal state round-trips both for a tab that is never woken. A wake carries both into the live tab (`TabCarry`), and a muted tab is re-muted on landing.
5. **Closing an unloaded card is closing a tab.** Its children move to its parent, as `destroy_tab` does. Today a failed card goes through `remove_node`, which leaves children naming a removed parent.

/// starts at launch), waking (a spawn in flight), or failed (its engine
/// couldn't start: a crash restart, a restore or a retry). The card keeps
/// the tab where it was, and in the saved session as a plain tab. Opening

    /// Starts an unloaded tab's engine (`UnloadedTabPayload`) on `kind`.
    /// The card stays, showing a spinner, until the outcome replaces it:
    /// the live tab under the same id, or a failed card with the new
    /// error. Ignored while a wake is already in flight.
    fn wake_tab(&mut self, id: &str, kind: EngineKind) {
        let Some(node) = self.nodes.get_mut(id) else { return };
        let (parent, group, pos, color) = (node.parent.clone(), node.group.clone(), node.pos, node.color);
        let NodePayload::Unloaded(tab) = &mut node.payload else { return };
        if tab.state == UnloadedState::Waking {
            return;
        }
        tab.state = UnloadedState::Waking;
        self.wakes_in_flight.insert(id.to_string());
        let carry = TabCarry { pinned: tab.pinned, color, zoom_factor: tab.zoom_factor };
        let url = tab.url.clone();
        let vel = egui::Vec2::ZERO;
        let (id, purpose, fallback_kind) = (id.to_string(), SpawnPurpose::Respawn, None);
        self.respawn_tab(TabSpawn { id, url, kind, parent, group, pos, vel, purpose, carry, fallback_kind });
    }
