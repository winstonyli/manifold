Defects found, from reading (2-4 since reproduced by ignored tests, PARKED "Worker pool defect tests"; 1 and 5 by none): (1) a PDF render panic kills its worker with no result, so the card spins for ever, and once both workers are dead `request` drops jobs silently (panic sources are few: thread-spawn failure and unreviewed callees); (2) two jobs for one id can finish in either order and results carry no job identity, so an old result or `Err` can overwrite the new state; (3) in PDF `State`, a second `begin` overwrites the first `Cancel` and the first `finish` removes the second's, so that render can't be cancelled; (4) `Err("cancelled")` is toasted as "Couldn't open PDF" if a node with that id exists by then (session teardown then reload of the same ids); (5) `cancel` of a queued PDF then `request` leaves two queue entries.
