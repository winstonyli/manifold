# Typed card ids Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (inline). Steps use checkbox (`- [ ]`) syntax.

**Goal:** Replace the `String` card key with two `Copy` 16-byte types, so the per-card path stops allocating ids: `NodeId` keys the stores (mirror, `App.nodes`, layout), `CardId` keys the UI (selection, hover, drag, focus, tab order, `CardEntry`).

**Architecture:** `CardId { hi: u64, lo: u64 }` is `NodeId`'s two fields. A non-node card (a `VirtualSource`'s or a JSON level's; one id kind, `Origin` tells them apart) sets the top bit of `lo` (a node's `counter` counts up from zero per launch, so its top bit is clear), keeps a 63-bit key chosen by its source in `lo`, and puts `fnv64(source name)` in `hi`. `CardId::node() -> Option<NodeId>` is the one bridge to the stores. Neither kind reaches the mirror, `App.nodes` or layout (tests assert `!mirror.has("virtual:fake:a")` and no layout entry), so the stores take `NodeId` and need no non-node case. Trail pages get a session-unique `serial`, and each `NavHistory` a session-unique `slot`, so trail ids need no `epoch` and no table.

**Tech Stack:** Rust, egui, foldhash. No new dependencies.

**Spec:** none; the decisions are in this session's transcript and `PARKED.md` (`NodeIx`, "Re-key every node-keyed collection at once"). Decisions taken: (1) `CardId` as above; (2a) first step re-keys mirror, `App.nodes`, layout, selection and the card loop, with no `to_string` on the per-card path; (3a) tests build real `NodeId`s through one helper; (14b) the source tag is a hash of the kind's name (`VirtualSource::name()`, or `"json"`); (c) trail page keys use a stable serial, not index+epoch. Added by the stress test (round 1): JSON-level card ids hashed from `(node id, pointer)`; the trail slot lives on `NavHistory`, not in `TrailSource`.

## Review Focus

0. JSON-level cards have ids `<json node id>#<pointer>` (unbounded pointer text), hashed into the shared non-node kind. Two cards on one level must never share an id, and a card must keep its id when a sibling is expanded. (Task 3b)
1. A node whose `counter` has its top bit set would read as non-node. `CardId::from(NodeId)` `debug_assert`s it; the counter is a per-launch count, so only a hostile or corrupt journal op can reach it. (Task 1)
2. A stale trail id (hover, selection, drag, `trail_menu`) after the page is evicted must resolve to nothing, never to another page. (Task 3)
3. Two sources whose names hash to the same 64 bits, or a source named `json`, must fail loudly in debug builds at registration. (Task 1)
4. Selection that contains a virtual id for a source that is no longer registered (`virtual:gone:x`, `virtual_source.rs:875`) must still be pruned. (Task 4)
5. The gate and `EXPORTSTATE` consume card ids as opaque strings plus a `"virtual"` key; the printed form must round-trip (`Display` then `FromStr`). (Task 1, Task 4)

### Task 1: `CardId` and the registration check (done as built)

**Built:** `crates/manifold/src/card_id.rs`: `CardId { hi, lo }` (16 bytes, `Copy`, `Hash`, `Ord`), `CardId::virt(source, key)`, `node()`, `is_virtual()`, `source_tag()`, `key()`, `From<NodeId>`, `Display`/`FromStr` (a node prints as `NodeId` does; a non-node as `virtual:{tag:016x}:{key:x}`), `const fn fnv64(parts)`, `JSON_SOURCE = "json"`, `assert_distinct_tags(names)`, and `#[cfg(test)] testutil::{node, card}`. `App::register_virtual_source` (`virtual_source.rs`, test-only) replaces the bare `push` in tests and calls the check; the production `vec!` is covered by `the_default_sources_have_distinct_tags`. The module carries `#![allow(dead_code, reason = ...)]` until Task 4 adopts it; Task 4 removes the allow.

**Ruling 1 (changes the plan):** the non-node marker is the top bit of `lo`, not the top 16 bits of `hi`, and `hi` holds the full 64-bit `fnv64(source name)`. Why: `ActorId::random()` makes a new actor every launch and each launch's nodes persist, so reserving actor values would eventually hit a real journal (about 1.5% after 1,000 launches), while a per-launch counter never reaches 2^63. Cost if wrong: a hostile or corrupt op with a counter at or above 2^63 reads as non-node (`debug_assert` in `From<NodeId>`). `ActorId` and `store/model.rs` are untouched.

**Ruling 2:** `assert_distinct_tags` takes names, not injected tags (a 64-bit clash cannot be built in a test); the tests cover a repeated name and the reserved `json`.

### Tasks 2 and 3: page serials, tab slots and trail ids (done as built, one commit)

**Built:** `nav_history.rs`: `Entry.serial` (`#[serde(skip)]`, assigned from `next_serial` on push and `0..n` by `renumber()` on load and in `with_tree`), `NavHistory.slot: Slot` (`Default` draws a process-wide `AtomicU32`; `NavHistory` is not `Clone`), `serial_of` (test-only), `index_of`, `TrailPage.serial`. `trail_strip.rs`: `page_card(history, serial) -> CardId = CardId::virt("trail", slot << 32 | serial)`, `is_page_id`, `live_page(app, id)` (parse, check the tag, find the history by slot, `index_of(serial)`); `ID_PREFIX`, `page_ids`, `TrailSource::page_id` and the epoch comparison are gone. Emit sites call `.to_string()` and `live_page` parses: the seam Task 4 deletes. `TrailPage.entry` was read only by one test once ids stopped using it, so it is deleted.

**Ruling 3 (changes the plan):** `NavHistory::epoch` stays. A second consumer exists that the plan's pre-flight grep missed: an open Back/Forward popup recentres when an eviction renumbers the pages (`popups/dropdowns.rs`, `the_popup_recentres_when_the_trail_is_renumbered_under_it`). Only its use in page ids is gone; its doc comment now says so. Cost if wrong: none, one counter.

**Ruling 4:** Tasks 2 and 3 are one commit. Task 2's API (`index_of`, `slot`, `serial`) is dead code under `clippy -D warnings` until Task 3 uses it.

**Tests:** `a_pages_serial_survives_an_eviction_of_an_earlier_page`, `an_evicted_pages_serial_resolves_to_nothing`, `every_page_of_a_tree_has_its_own_serial_and_the_strip_gets_it`, `two_histories_get_different_slots`, `serials_are_assigned_in_order_on_load_and_the_next_push_continues`, and `a_page_evicted_at_the_cap_retires_only_its_own_id` (Review Focus 2: the evicted page's id names nothing, the 49 survivors keep their ids and resolve to the shifted indices). Full suite 1461 passed, clippy clean.

### Tasks 3b and 4: JSON-level ids and UI identity are `CardId` (done as built, one commit)

**Built:** `CardEntry.id`, `LevelEdge.{from_id, to_id}`, `Interaction.{selected, hovered, dragging, drag_moved, drag_origin, peek_suppressed, focus_new_note}`, `CardPass.{order, pick_targets, connect_target, drop_preview}`, `GraphAction::Drop`, `VirtualSource::{edges, on_drop}`, `menus.trail_menu` and the tab-order and digit-jump paths are `CardId`. `CardId` gained `Serialize` (through `Display`), `stored(&str)` (parses a `NodeId`, panics otherwise: seam 1), `widget()` and `editor()` (the one definition of a card's egui ids; the `link_handle` id hashes the `CardId` too). A call from a `CardId` into a `&str` store goes through `id.node()` (`apply_drop` returns early when either end is virtual) or `id.to_string()` (seam 2, a stored card's key is its `NodeId` text). `JsonLevel.ids: Vec<CardId>` is `CardId::virt("json", fnv64(&[node, "#", pointer]))`, computed in `relayout`; `card_of` and `by_id` had no caller and are deleted. `is_virtual_id` and its three guards in `session_sync/edits.rs` are deleted: no virtual id reaches `edit_pos`, `edit_field`, `edit_group` or `edit_parent`, because every caller converts through `node()`. `debug_export` sorts `selected` by its printed text.

**Ruling 6:** `assert_distinct_tags` is `#[cfg(test)]`. Sources are fixed at construction (`vec![TrailSource]`), only tests call `register_virtual_source`, and `the_default_sources_have_distinct_tags` covers the production list; a debug-only function nothing production calls was dead code under `-D warnings`. Cost if wrong: a runtime-registered source would need the check moved back.

**Ruling 7:** every test fixture that hand-built a stored id (`"a"`, `"n"`, `"g"`, `"live"`) now uses real `NodeId` text (`"0000000000000001-N"`, `testutil::{node, card}`), because `level_items` parses stored ids through `CardId::stored`. Task 5 makes such ids unrepresentable, so these were going to change anyway.

**Tests added:** `two_cards_of_one_level_get_different_ids`, `a_cards_id_is_unchanged_when_a_sibling_is_expanded`, `a_card_of_another_json_node_with_the_same_pointer_gets_another_id` (Review Focus 0); `the_selection_actions_split_on_the_id_kind_not_on_what_sources_list`; `selection_prunes_a_virtual_id_whose_source_is_unregistered` (Review Focus 4); `exportstate_prints_a_card_id_that_parses_back` (Review Focus 5); the Task 1 `fake::id` helper replaces the `"virtual:fake:x"` literals. The mixed-selection pin per action family is `selection_actions_act_on_stored_cards_and_leave_a_virtual_id_alone` and `every_write_entry_point_leaves_a_virtual_id_out_of_the_store_and_the_layout` (pin, close, group, every drop effect, drag release). Full suite 1466 passed, clippy and fmt clean.

## Expected value (state it, then measure)

The `to_string`/`position`/string-compare work is a small share of `draw_graph_card` (17% of main-thread samples at 400 cards, of which the allocator and memcpy leaves were about 26%). Item 2's earlier 34% vertex cut produced no frame-time win either. Do not expect more than a few percent; Task 4's measurement is there so Task 5 is an informed decision. The case for the work also rests on removing the `"virtual:"` string convention and `epoch`, not only on speed.
