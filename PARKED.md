Chosen over hub bodies, normalised pair edges and a label-as-soft-group region (survey 2026-11-01, v2-v4). *Strength curve (prototype w1, 2026-11-01, 400 cards, labels of 6, 20, 60 plus optionally a 400-card status label, pull as a velocity kick toward the centroid, 400 steps; radius = mean member distance to centroid over `REST_LENGTH`*sqrt(k), a tight non-overlapping pack is about 0.2, no pull gives 1.6/1.0/0.55):* a constant strength piles members up (0.09-0.15) and the status label makes 4060 overlapping pairs (312 with no pull); 1/sqrt(k) packs (0.17-0.29) but the status label still raises overlaps to 897; 1/k leaves the status label harmless (451) but barely pulls large sets (0.5-0.8); **0.5*ln(N/k)/ln(N)** (idf over the level's card count N) packs (0.24-0.27, 421 overlaps) and gives a set of every card strength 0, so the status label changes nothing (identical to without). Pull must stay below the overlap push (about 640 at the cap): strength times `SPRING_STRENGTH` times the pack radius under about 600, so scale about 0.25-0.5. **No real labelled document exists on this machine** (the profile holds no label nodes; checked 2026-11-01), so the second prototype used 300 cards with 25 Zipf-sized labels (150/rank, at least 3) over random members, which overlap (about 1.9 labels per card); same pull, 400 and 2000 steps agree, so it is steady state, not unconverged. Result: the disjoint numbers above do not transfer. Cohesion (mean within/across distance of labels of 3-60 cards; no pull 1.0) costs overlapping card pairs: 1/sqrt(k) 0.57 with 821 overlapping pairs, idf 0.25 0.72 with 652, idf 0.5 0.58 with 840, idf 1 0.50 with 1091, against 144-222 with no pull. A per-card share (a card in m labels feels 1/m of each pull) loosens cohesion more than it cuts overlaps (idf 0.25: 0.94 with 598). The idf curve depends on N: adding 100 unlabelled cards to 300 strengthens every pull (idf 0.25: 0.72 to 0.62). So the cohort needs an overlap-aware limit, not only a curve: the pull should saturate below the overlap push (about 640, `OVERLAP_STRENGTH * OVERLAP_MAX`) the way repulsion is clamped by `REPULSION_SOFT_DISTANCE`; untested. **Clamp tested (z1, 2026-11-01), negative:** the same Zipf set with each member's cohort force clamped to a cap (idf 0.5, 1, 2; caps 320, 160, 80, 40 against the overlap push of 640): any cap of 320 or less removes the cohesion (within/across 0.98-1.00, no pull is 1.01) while overlapping pairs stay above no pull (492-669 at cap 320 against 186; 340-498 at cap 160; 224-440 at cap 40), so the clamp trades cohesion for overlaps along the same line instead of separating them.
